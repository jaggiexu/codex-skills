# Test Case Generate

根据一次调用中提供的全部需求材料，生成一份中文 APP 测试用例 XMind。Skill 会区分有明确依据的核心用例、根据测试方法推导的衍生用例，以及信息不足时的待确认用例，避免将推测当成已确认需求。

## 适用场景

- 根据产品需求文档生成 APP 功能测试用例
- 将截图、流程说明、表格和补充消息合并为同一个需求
- 需要用 XMind 组织测试点并保留需求追踪关系
- 系统覆盖正常、异常、边界、状态和业务规则场景
- 需求暂不完整，但希望先产出可执行部分并标记待确认项

本 Skill 默认面向 APP 功能测试，不会自动生成 UI 自动化脚本，也不能替代测试人员对业务风险和范围的最终评审。

## 支持的输入

一次调用中提供的以下材料会视为同一需求的组成部分：

- 截图和普通图片
- Markdown 或纯文本说明
- Word 文档
- PDF 文件
- Excel 工作簿
- 包含多份材料的文件夹
- 用户已授权且当前环境可访问的网页
- 当前对话中的补充要求和限制

建议在同一条消息中附上同一需求的全部材料。不同项目或互不相关的需求最好分开调用。

## 主要能力

- 建立输入清单，减少附件遗漏
- 提取页面、流程、字段、规则、状态和异常信息
- 使用等价类、边界值、状态迁移和错误推测设计用例
- 严格区分核心、衍生和待确认三类用例
- 合并重复场景，同时保留有意义的前置条件或结果差异
- 记录优先级、需求编号、设计方法、步骤和标签
- 将全部内容生成到一份结构清晰的 XMind 文件
- 检查用例数据结构及 XMind 文件完整性
- 在项目目录内维护隔离的学习记录，辅助后续迭代

## 安装

将本目录完整复制到个人 Skill 目录：

```text
~/.agents/skills/test-case-generate/
```

请保留完整结构：

```text
test-case-generate/
├── SKILL.md
├── agents/
├── assets/
├── references/
├── scripts/
└── README.md
```

脚本需要 Python 3。模板、数据结构和处理脚本均已包含在 Skill 中。重新打开 Codex 或开始新任务后，确认 Skill 列表中能够看到 `test-case-generate`。

## 调用方法

在包含需求材料的同一条消息中明确调用：

```text
$test-case-generate

请根据本条消息附带的需求文档、三张页面截图和字段规则表，生成一份中文 APP XMind 测试用例。
需求编号：APP-LOGIN-001
```

也可以补充测试重点和范围：

```text
$test-case-generate

附件均属于“手机号登录”同一个需求。
重点覆盖手机号输入、验证码发送、倒计时、重复请求、错误验证码、登录成功和网络异常。
Android 与 iOS 规则相同，不要重复生成平台用例。
```

调用后无需再发送“开始生成”。只要材料可读且输出位置可写，Skill 会直接分析并生成结果。

## 建议提供的信息

| 信息 | 作用 |
| --- | --- |
| 需求编号 | 建立用例与需求的追踪关系 |
| 需求名称和范围 | 确定根主题和模块边界 |
| 页面或流程截图 | 提供可见控件、文案及跳转依据 |
| 字段规则 | 生成等价类和边界值用例 |
| 状态及业务规则 | 生成状态迁移和组合场景 |
| 明确排除项 | 防止扩展到本次不测试的内容 |
| 平台差异 | 仅在真实存在差异时拆分平台用例 |
| 项目目录 | 确定 XMind 和项目记忆的保存位置 |

## 工作流程

1. 统计并登记本轮全部输入材料。
2. 按文件类型读取文本、表格、截图和页面信息。
3. 提取明确的需求规则及其来源。
4. 初始化或读取当前项目独立的测试记忆。
5. 运用测试方法补充必要的正常、异常和边界场景。
6. 将用例划分为核心、衍生和待确认三类。
7. 合并重复场景，检查步骤、结果和追踪关系。
8. 校验数据并生成一个 XMind 文件。
9. 验证 XMind 可解包且核心内容存在。
10. 返回文件位置、分类数量和待确认事项。

## 三类用例的区别

### 核心用例

能够直接追溯到需求文字、表格、截图或明确补充说明。不会加入材料中不存在的后台规则或隐藏限制。

### 衍生用例

依据等价类、边界值、状态迁移、错误推测及常见 APP 风险合理推导，并明确标识为衍生内容，便于评审是否纳入正式范围。

### 待确认用例

需求有歧义、材料冲突或缺少预期结果时，不随意补全业务结论，而是生成待确认项。普通歧义不会阻断整份 XMind 的产出。

## 测试设计方法

| 方法 | 典型用途 | 示例 |
| --- | --- | --- |
| 等价类 | 输入值、账号状态、权限分类 | 合法与非法手机号 |
| 边界值 | 长度、金额、次数、日期 | 最小值、最大值及相邻值 |
| 状态迁移 | 页面和业务状态变化 | 未登录、验证码已发送、登录成功 |
| 错误推测 | 网络、重复操作、异常返回 | 重复点击、超时、服务失败 |

设计方法会记录在用例中，方便评审覆盖思路和用例来源。

## 输出内容

默认输出到当前项目：

```text
<project>/test-docs/<requirement-id>_testcases_<timestamp>.xmind
```

每次调用只生成一份汇总 XMind，典型结构为：

```text
需求名称
├── 核心用例
│   ├── 模块 A
│   └── 模块 B
├── 衍生用例
│   ├── 边界与异常
│   └── 状态与组合
└── 待确认
    └── 需求歧义或缺失规则
```

每条用例主要包含：所属模块、用例标题、优先级、需求编号、设计方法、前置条件（适用时）、步骤和预期结果、分类标签及备注（适用时）。

## 使用效果示例

若需求只说明“输入手机号并获取验证码”，Skill 可能形成：

```text
核心用例
- 输入符合需求格式的手机号，验证码发送成功
- 倒计时期间按钮状态符合页面说明

衍生用例
- 手机号为空、长度不足、长度超出或包含非法字符
- 快速重复点击发送按钮
- 请求超时或断网后的页面反馈

待确认
- 同一手机号每日最大发送次数未说明
- 验证码有效期与错误次数上限未说明
```

实际效果包括：

- 一次整合多种格式材料，减少手工搬运
- 区分需求事实和测试推导，降低错误假设风险
- 用统一字段组织用例，方便 XMind 评审和维护
- 系统补充边界、异常和状态场景
- 集中列出无法确定的问题，方便产品、开发和测试对齐

结果仍需结合真实接口规则、测试环境和业务风险评审。Skill 不能保证发现所有缺陷，也不会虚构没有依据的服务端行为。

## 项目记忆

同一项目的辅助记录默认保存在：

```text
<project>/.test-case-memory/
```

- 每个项目相互隔离，不把一个项目的规则带入另一个项目。
- 记忆存放在项目目录，不会写回已安装的 Skill。
- 新需求仍以本轮材料为准，历史记录不能覆盖明确的新要求。
- 如不希望保留项目记忆，可在调用时明确说明。

## 隐私和限制

- 公开 Skill 不包含真实项目数据和个人信息。
- 需求材料、XMind 和项目记忆默认保存在用户指定的本地目录。
- 读取登录网页需要用户授权且当前环境能够访问。
- Skill 不会主动把需求、截图或结果上传到 GitHub。
- 发布结果前，应检查需求名称、账号、截图和业务数据是否需要脱敏。
- 加密、损坏或无权访问的文件可能无法完整分析。
- 没有有效需求材料时，不会凭空生成正式用例。
- Android 和 iOS 默认不重复拆分，除非材料明确存在平台差异。
- 截图只证明可见信息，不能证明服务端隐藏规则。
- 输出是测试设计文档，不是自动化代码或测试执行报告。
