# Daily Plan HTML Generator

将项目目标、截止日期、当前进度、约束和参考材料，整理为一份可离线使用的中文每日执行计划 HTML。页面包含甘特图、里程碑、每日验收标准、阶段筛选、进度统计、本地状态保存及 JSON 导入/导出。

## 适用场景

- 论文写作、实验复现、产品开发、备考等有明确起止日期的项目
- 已有总体计划，需要继续拆成每天可执行、可验收的任务
- 多份材料中包含目标、进度和限制，需要统一口径后再排期
- 希望用一个本地 HTML 页面持续跟踪完成情况

如果只需要简单文字建议、日历提醒或多人实时协作系统，则不建议使用本 Skill。

## 主要能力

- 从当前对话、附件及已有计划中提取项目事实
- 识别目标、依赖、截止日期、风险和可投入时间
- 将工作拆成连续阶段、关键里程碑和逐日任务
- 默认每天设置一个主任务，减少模糊任务堆叠
- 为每日任务提供行动、预计工时及可核验的验收标准
- 生成覆盖完整日期范围的甘特图
- 支持阶段筛选、任务勾选和总体/分阶段进度统计
- 使用浏览器本地存储保存状态，并支持 JSON 备份与恢复
- 输出一个自包含 HTML，无需部署即可打开

## 安装

将本目录完整复制到个人 Skill 目录：

```text
~/.agents/skills/generate-daily-plan-html/
```

应保留以下结构：

```text
generate-daily-plan-html/
├── SKILL.md
├── agents/
├── assets/
├── references/
└── README.md
```

重新打开 Codex 或开始新任务后，确认 Skill 列表中能够看到 `generate-daily-plan-html`。

## 调用方法

在对话中输入 Skill 名称，并提供计划所需信息：

```text
$generate-daily-plan-html

请根据我提供的材料，生成 9 月 1 日至 10 月 15 日的每日执行计划 HTML。
工作日每天可投入 3 小时，周末可投入 6 小时。
目标是完成论文修改、补充实验和提交前检查。
```

也可以同时提供总体计划、评审意见或已有 HTML：

```text
$generate-daily-plan-html

参考附件中的总体计划和评审意见生成完整每日排期。
要求：
1. 日期覆盖 8 月 22 日至 10 月 15 日；
2. 实验先于结果分析；
3. 每天必须有明确验收标准；
4. 保留模板的甘特图和进度记录功能。
```

## 建议提供的信息

| 信息 | 示例 |
| --- | --- |
| 起止日期 | 8 月 22 日至 10 月 15 日 |
| 最终目标 | 完成论文定稿并提交 |
| 当前进度 | 正文已完成，实验结果待补充 |
| 硬性节点 | 9 月 20 日提交导师审阅 |
| 可用时间 | 工作日 3 小时，周末 6 小时 |
| 任务依赖 | 数据清洗完成后才能重新训练 |
| 资源限制 | 只在本地设备训练，需预留运行时间 |
| 参考材料 | 总体计划、意见表、论文和代码说明 |

若材料存在冲突，Skill 会优先采用最新、最明确的要求，并在计划中体现必要的假设和风险。

## 工作流程

1. 读取本轮对话和用户提供的材料。
2. 汇总项目状态、目标和硬约束。
3. 划分连续阶段并确定里程碑。
4. 从最终交付日期倒推任务依赖。
5. 为日期范围内每一天生成主任务和验收标准。
6. 将项目内容写入固定 HTML 模板。
7. 检查日期覆盖、任务编号、筛选、状态保存及 JSON 导入/导出。
8. 返回文件位置以及日期、任务和阶段统计。

## 输出内容

生成页面固定包含：

1. 页面标题、日期范围和操作按钮
2. 三项核心结果与执行承诺
3. 项目基线和证据信息
4. 关键里程碑
5. 总体及分阶段进度
6. 完整甘特图
7. 可按阶段筛选的每日任务
8. 执行规则和提醒

每个每日任务通常包括日期、阶段、主任务、具体行动、交付物或验收标准、建议时间段及预计工时。

## 使用效果示例

对于“六周内完成论文实验和写作”，输出不会只写“继续实验”，而会拆成类似：

```text
日期：9 月 6 日
阶段：实验基线复现
主任务：完成基线模型第二组固定随机种子训练
执行动作：使用冻结的数据划分运行训练，保存日志、配置和指标
验收标准：形成包含参数、运行时长、PR-AUC、F1 和 Recall 的结果记录，文件可复查
预计投入：3 小时主动操作 + 后台运行
```

最终可获得以下效果：

- 将抽象目标转成每天可直接开始的动作
- 用验收标准减少“做了但无法确认是否完成”的情况
- 通过甘特图看清依赖、阶段重叠和缓冲时间
- 通过勾选和进度条了解真实完成度
- 通过 JSON 导出备份并迁移进度

Skill 负责生成和维护计划，不会自动执行任务，也不能保证项目结果；计划质量取决于输入材料和后续执行。

## 进度保存与迁移

- 完成状态保存在当前浏览器的本地存储中。
- 更换电脑、浏览器或文件位置前，建议先导出 JSON。
- 在另一环境打开 HTML 后，可导入 JSON 恢复状态。
- HTML 不会自动同步到云端、日历或项目管理平台。

## 隐私和限制

- 输出为本地自包含 HTML，页面本身无需连接外部服务。
- Skill 不会主动把源材料或结果发布到 GitHub。
- 公开结果前，应检查项目名称、路径、任务和备注中的敏感信息。
- 新对话不会自动拥有旧对话的全部背景，重要事实应在当前调用中重新提供。
- 模板默认“一天一个主任务”；多人或多班次安排需在提示中明确说明。
- 目标或截止日期变化后，建议重新调用 Skill 更新排期。
